P02 A generated sentence includes a token with probability below the chosen confidence threshold. In FLARE, does the system keep that sentence or fetch evidence and rewrite it?
Expected: Retrieve using the predicted sentence with low-confidence tokens masked, then regenerate; do not reverse the threshold.
Status: partial
In FLARE’s direct method, the model first generates a temporary next sentence and checks its token probabilities. Retrieval is triggered if any token is below the confidence threshold; if all tokens meet the threshold, the sentence is accepted without extra retrieval. When triggered, the system retrieves relevant documents and regenerates the sentence using them.
FLARE uses the anticipated next sentence to formulate a forward-looking search query. Its implicit query formulation masks low-confidence tokens so that uncertain or erroneous words do not dominate retrieval; the retrieved evidence is then used to regenerate the sentence.

P05 Is a maximum ColBERT token match averaged or summed over the query tokens?
Expected: State sum of query-token MaxSim values, not an average.
Status: source_linked_explanation
ColBERT computes MaxSim: for each query-token vector it takes the maximum similarity to a document-token vector, then sums those maxima across query tokens. This produces the query–document relevance score.

P06 Which wins on retrieval quality, SPLADE or Contriever, when both are evaluated on the same Kannada legal corpus?
Expected: Explicitly state that an appropriate shared benchmark result is not established; no invented winner.
Status: partial
SPLADE learns sparse lexical representations for queries and documents, including vocabulary expansion and term weighting. Sparse weights allow retrieval with an inverted index rather than requiring a dense nearest-neighbour representation.
Contriever is a dense retriever trained with contrastive learning without requiring labelled query–passage relevance pairs for its unsupervised pre-training. Its representation approach is dense rather than a sparse vocabulary-weight representation.

P07 What is the main difference between FiD's evidence fusion and REPLUG's document ensemble?
Expected: Explain FiD independent passage encoding/decoder fusion and REPLUG separate passes/probability mixture.
Status: source_linked_explanation
Fusion-in-Decoder (FiD) concatenates the question with each retrieved passage and its title, then encodes each passage independently. The decoder attends across the concatenated encoded representations of all passages to generate the answer. Evidence is therefore fused in the decoder, rather than by jointly encoding all passages.
REPLUG prepends each retrieved document separately to the input context and runs the frozen language model separately for each document. It combines the resulting next-token probability distributions using a similarity-weighted average: document weights are the exponentiated document-context similarity scores, normalised across the retrieved set. This uses several documents without concatenating them all into one input window.
